# پیاده‌سازی دسترسی مدیران سایت مشتری در Asumi

**هدف:** مدیر فعال ERP هر سایت مشتری بتواند از Asumi فقط عملیات Docker Control همان سایت را مدیریت کند؛ مدیر اصلی Asumi همچنان میزبان و همهٔ سایت‌ها را مدیریت می‌کند.

**محدوده:** چهار دامنهٔ ثابت `boller.ir`، `dehati.ir`، `denroom.ir` و `veederakht.ir`. حساب جدید با ایمیل منبع ساخته می‌شود، ایمیل یا رمز برایش ارسال/کپی نمی‌شود، و نقش Press Admin به آن داده نمی‌شود.

## گام‌ها

- [x] در Agent یک مسیر HMAC-محافظت‌شده و فقط‌خواندنی برای فهرست System Managerهای فعال هر دامنهٔ مجاز اضافه شد؛ ورودی دلخواه به Bench یا SQL راه ندارد.
- [x] در Asumi برای هر Docker Control Site فهرست مدیران مجاز، زمان و اجراکنندهٔ آخرین همگام‌سازی ذخیره می‌شود.
- [x] دسترسی API سایت فقط از روی نگاشت همان دامنه محاسبه می‌شود؛ مالک تیم هم بدون نگاشت صریح دسترسی ندارد و مدیر مشتری فقط عملیات `SITE_SCOPED_ACTIONS` را می‌گیرد.
- [x] API همگام‌سازی فقط برای مدیر اصلی Asumi باز است؛ کاربر موجود فعال یا ارتقا داده نمی‌شود، کاربر جدید فقط نقش Press Member می‌گیرد و عضو تیم تجاری نمی‌شود، و ایمیلی ارسال نمی‌شود.
- [x] مجوز مدیران منبع در همگام‌سازی دستی و زمان‌بندی روزانه تطبیق داده می‌شود؛ در خطای Agent نگاشت جاری حفظ می‌شود و دسترسی تازه ساخته نمی‌شود.
- [x] Boot و Router اجازه می‌دهند مدیر دارای نگاشت فقط صفحهٔ Docker Control را باز کند، بدون دسترسی به routeهای عمومی Press Admin.
- [x] صفحهٔ مدیر اصلی شمار مدیران، آخرین همگام‌سازی و دکمهٔ هر سایت را نشان می‌دهد؛ کاربران تازه باید خودشان از بازیابی رمز Asumi استفاده کنند.
- [x] تست عامل HMAC و allowlist، همگام‌سازی، محدودیت دامنه، کاربر غیرفعال، دسترسی تک‌سایت، رد دسترسی میزبان و guard رابط اضافه و اجرا شد.
- [x] تست‌های هدفمند و build کامل هر دو dashboard اجرا شد؛ بکاپ تازه گرفته شد، Asumi migrate/reload شد و همگام‌سازی زندهٔ هر چهار دامنه موفق بود.

## معیارهای پذیرش

- مدیر سایت A فقط A را می‌بیند و نمی‌تواند به B یا عملیات Bench/میزبان دسترسی پیدا کند.
- مدیر غیرفعال/حذف‌شده در منبع با همگام‌سازی بعدی از همان سایت حذف می‌شود؛ حساب مرکزی خاموش نمی‌شود.
- خطای شبکه یا پاسخ نامعتبر Agent دسترسی فعلی را پاک نمی‌کند و مدیر تازه‌ای اضافه نمی‌کند.
- هیچ رمز یا دعوت‌نامه‌ای کپی یا ارسال نمی‌شود؛ کاربر برای ورود به Asumi رمز را خودش از مسیر بازیابی تنظیم می‌کند.
- مدیر اصلی Asumi کماکان همهٔ سایت‌ها و عملیات میزبان را می‌بیند.

## بررسی زنده

- ۲۰ نگاشت برای ۱۷ کاربر یکتا از چهار سایت ذخیره شد؛ ۱۶ کاربر سایت‌محور فقط نقش Press Member دارند و عضو هیچ تیم تجاری نیستند.
- برای هر ۱۶ حساب سایت‌محور، API فقط دامنه‌های نگاشت‌شده را نمایش داد؛ عملیات دامنهٔ دیگر و سرویس میزبان رد شد. یک حساب مرکزی که از قبل مدیر بود، دسترسی قبلی خود را حفظ کرد.
- بکاپ کامل پیش از مهاجرت: `20261012_211612-asumi_ir`.
- پس از reload، ۱۲ worker آنلاین بودند؛ مسیرهای عمومی و دارایی‌های اصلی Asumi HTTP 200 دادند.
