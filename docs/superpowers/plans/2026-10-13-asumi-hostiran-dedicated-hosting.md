# برنامهٔ اجرای میزبانی اختصاصی هاست‌ایران

## هدف و محدودیت‌ها

مدل فروش ساخت سایت جدید را از Docker مشترک به VPS جداگانهٔ هاست‌ایران تغییر بده و از Press برای تنظیم سرور، بنچ خصوصی و سایت استفاده کن. پلن ارتقای سایت موجود روی همان Server باقی بماند. خرید VPS و اجرای migration روی سایت واقعی در تست ممنوع است. پیاده‌سازی باید fail-closed بماند تا پرداخت زنده و زیرساخت آماده باشند.

## کارها

### 1. آزمون‌های مدل میزبانی و قیمت

- تست‌های شکست‌خورده برای تشخیص پلن «ساخت سایت جدید» در برابر «ارتقای سایت موجود» اضافه کن.
- اعتبارسنجی SKU هاست‌ایران، هزینهٔ ماهانهٔ ارائه‌دهنده، منابع VPS و کف قیمت را اضافه کن؛ دوره/واحد پولی و تبدیل تومان/ریال را شفاف نگه دار.
- پیش‌نویس پلن سایت جدید را disabled و با `dedicated_server_plan` بساز؛ بنچ Docker را از انتخاب پلن‌ها و ظرفیت آن حذف کن.
- مطمئن شو تغییر مسیر تحویل پلن دارای سفارش یا اشتراک فعال رد می‌شود.

### 2. نگهداری سفارش و خرید دستی VPS

- فیلدهای read-only/مدیرمحور سفارش را برای HostIran order reference، SKU/هزینه snapshot، Server و Site Group Deploy اضافه کن؛ credential ذخیره نکن.
- پس از callback پرداخت، سفارش ساخت سایت جدید را در مرحلهٔ تهیهٔ VPS نگه دار و آن را به worker ساخت سایت Docker نفرست.
- endpoint مدیر برای ثبت VPS آماده‌شده بساز؛ قبل از اجرا پرداخت واقعی، sandbox خاموش، انطباق plan/amount/interval، تیم Server، setup وضعیت Agent، ظرفیت، Proxy Server و sourceهای اپ‌ها را اعتبارسنجی کن.
- سفارش را idempotent به `Site Group Deploy` استاندارد Press وصل کن؛ مشخصات SiteGroupDeploy از snapshot سفارش ساخته شود، نه از payload آزاد مدیر.

### 3. تحویل سایت روی VPS

- Site Group Deploy را با HostIran server منتخب، نسخه، برنامه‌های مجاز، پلن و تیم سفارش بساز.
- در ایجاد Site، سفارش دقیق را به Site وصل کن و check `is_verified_hosting_site_creation` را به Server مورد انتظار مقید کن.
- callback سایت و Site Group Deploy را به یک order lifecycle وصل کن. فقط موفقیت ساخت Site، Agent، proxy/TLS و domain آن را Active کند.
- retry و failure باید هم deployment موجود را ادامه دهند و هم از ساخت سایت تکراری جلوگیری کنند.
- renew/expiry همان سایت را حفظ کند و داده یا VPS را حذف نکند.

### 4. پنل مشتری و مدیر

- پنل مدیر: قیمت هزینهٔ VPS، SKU، ثبت HostIran reference، انتساب Server، شروع تحویل، deployment/status و خطا را نمایش دهد.
- پنل مشتری: مسیر تحویل را با واژه‌های ساده نشان دهد: پرداخت، تهیهٔ سرور، آماده‌سازی سایت، فعال.
- برای Server نامرتبط/ناقص دکمهٔ تحویل غیرفعال و علت مشخص باشد.
- بنچ مشترک در UI پلن جدید/آمادگی حذف شود؛ فروش ارتقای سایت موجود از مسیر جدا باقی بماند.

### 5. بررسی و انتشار

- تست واحد و Frappe integration برای هر transition، permission، mapping، validation، idempotency، failed delivery و retry اجرا کن.
- تست‌های dashboard و build را برای تغییرات UI اجرا کن.
- migration را روی سایت آزمایشی اجرا و ساختار DocType را بررسی کن.
- از Asumi و پنج سایت فعال backup بگیر؛ live checkout و readiness را دوباره بررسی کن.
- هیچ سفارش پولی، خرید VPS، DNS یا TLS واقعی برای تست نساز/تغییر نده.
- پس از آماده‌بودن همهٔ gateها، با پیام کامیت فارسی ثبت کن و فقط تغییرات لازم را منتشر کن.

## ریسک‌ها و gateها

- HostIran در حال حاضر اتصال خرید خودکار ندارد؛ فاز نخست خرید دستی است.
- هزینه و SKU هاست‌ایران باید هنگام خرید واقعی با حساب کاربر تأیید شوند؛ تخفیف ثبت‌نامی را هزینهٔ تمدید فرض نکن.
- Press Agent برای راه‌اندازی Server واقعی به دسترسی SSH و تنظیمات امن نیاز دارد؛ رمز/کلید نباید در آسومی commerce ذخیره شود.
- DNS/TLS به پراکسی و دامنهٔ فعال Press وابسته است؛ تا قبل از راه‌اندازی per-site domain routing فروش پلن جدید خاموش بماند.
- بازرسی آمادگی، فروش سایت جدید را تا آماده‌بودن Server/Bench/Proxy، SMTP، قیمت و پرداخت واقعی خاموش نگه می‌دارد.
