# میزبانی آسومی روی بنچ عمومی Press

## تصمیم

سایت جدید هر مشتری به‌صورت یک Press `Site` مستقل با پایگاه‌داده، دامنه، تیم، پلن و دسترسی خودش ساخته می‌شود. Press آن را با چرخهٔ عادی خود روی یک بنچ عمومیِ فعال و سازگار قرار می‌دهد؛ برای هر مشتری VPS جدا خریداری یا ایجاد نمی‌شود. مسیر ساخت اختصاصی هاست‌ایران که در دو کامیت اخیر اضافه شده، از فروش و تحویل سایت جدید کنار گذاشته می‌شود.

## تجربهٔ خرید و تحویل

1. مشتری پلن فعال «ساخت سایت جدید» را انتخاب می‌کند، زیردامنهٔ آزاد و برنامه‌های مجاز را می‌فرستد و پرداخت زرین‌پال را انجام می‌دهد.
2. پیش از پذیرش سفارش و دوباره پس از تأیید پرداخت، Press بررسی می‌کند که دامنهٔ ریشه، wildcard DNS و TLS، ایمیل دسترسی، پلن، برنامه‌ها و زیرساخت عمومیِ سازگار آماده باشند.
3. فقط پس از تأیید پرداخت واقعی، سفارش به `Provisioning` می‌رود. کارگر سفارش با هویت مشتری و تیم ثبت‌شده، مسیر معمول ساخت سایت Press را اجرا می‌کند. سرور و بنچ را مشتری تعیین نمی‌کند؛ Press از Release Group مجاز پلن، نسخه، برنامه‌ها، Cluster و پراکسی فعال، مقصد عمومی مناسب را انتخاب می‌کند.
4. سفارش به همان Press `Site` و Agent Job وصل می‌شود. تکرار کار همان سفارش یا همان سایت را ادامه می‌دهد و نام زیردامنه را دوباره مصرف نمی‌کند.
5. سفارش تنها وقتی `Active` می‌شود که Agent وضعیت Site را `Active` کرده باشد. شکست به `Provisioning Failed` تبدیل می‌شود و از جزئیات امن سفارش برای پیگیری و تلاش دوباره استفاده می‌شود.
6. تمدید، تعلیق و ارتقای پلن از همان Site Press موجود انجام می‌شود. این تغییر معماری برای خرید و نصب برنامه‌های Marketplace یا سفارش خدمات آسومی تغییری ایجاد نمی‌کند.

## آماده‌بودن زیرساخت

- Site Plan ساخت سایت باید یک پلن عمومی باشد (`private_bench_support=0`) و Release Groupهای عمومی مجاز، قیمت، دوره و حدود استفادهٔ لازم را داشته باشد.
- برای دامنهٔ `asumi.ir` باید Root Domain فعال و Cluster پیش‌فرض، حداقل یک Release Group عمومی فعال با نسخه و برنامه‌های لازم، بنچ فعال روی سرور عمومی، Agent قابل‌استفاده و پراکسی فعال متصل به دامنه ثبت شده باشند.
- انتخاب مقصد و ایجاد Site باید از منطق استاندارد Press پیروی کند. هیچ‌کدام از بنچ Docker خصوصی این اپ، ظرفیت Docker آن، سرور اختصاصی مشتری یا SKU و قیمت هاست‌ایران معیار آمادگی مسیر جدید نیست.
- اگر Press هیچ مقصد سازگاری پیدا نکند، پلن ساخت سایت برای خرید در دسترس نمی‌شود و تحویل سفارش موجود هم fail-closed می‌ماند؛ هیچ fallback پنهان به Docker یا VPS اجرا نمی‌شود.
- در بازبینی زندهٔ پیش از این طراحی، برای این مسیر بنچ عمومی، Release Group و اتصال پراکسیِ واجد شرایط پیدا نشده بود. بنابراین اصلاح کد به‌تنهایی فروش را فعال نمی‌کند؛ پس از انتشار، باید زیرساخت عمومی Press و رکوردهای DNS/TLS لازم آماده شوند.

## کنترل پرداخت و داده

- وضعیت «پرداخت‌شده» فقط با تأیید سمت‌سرور زرین‌پال ثبت می‌شود. حالت آزمایشی، نبود Merchant ID، یا خاموش‌بودن فروش میزبانی همچنان خرید عمومی را مسدود می‌کند.
- سمت سرور پلن، مبلغ، دوره، تیم، کاربر، وضعیت سفارش، زیردامنه، برنامه‌ها و مالکیت مقصد را دوباره بررسی می‌کند؛ ورودی مرورگر برای انتخاب سرور یا بنچ پذیرفته نمی‌شود.
- فیلدهای HostIran و Site Group Deploy که فقط برای VPS مشتری اضافه شدند، از پنل و API سفارش جدید حذف می‌شوند. رکوردهای قبلی، اگر وجود داشته باشند، با مهاجرت حذف یا فعال نمی‌شوند و پیش از پاک‌سازی هر دادهٔ عملیاتی بررسی خواهند شد.
- Siteها، پایگاه‌داده‌های جدا و Agentهای استاندارد Press را نگه می‌دارند. رمز مدیر سایت در سفارش یا لاگ کپی نمی‌شود؛ از سازوکار رمزنگاری‌شدهٔ Site و ابزار دسترسی مجاز خود Press استفاده می‌شود.

## معیارهای پذیرش

1. خرید سایت جدید فقط با پرداخت واقعیِ تأییدشده ممکن باشد و سفارش به سایت مشتری دیگری وصل نشود.
2. Site جدید با دامنه، تیم، پلن و برنامه‌های سفارش ساخته شود و Press آن را روی مقصد عمومیِ مجاز قرار دهد.
3. نبود بنچ، Release Group، پراکسی، Agent، DNS یا TLS سازگار، خرید را غیردسترس‌پذیر کند و تلاش تحویل را فعال نشان ندهد.
4. تکرار callback، worker یا retry، Site دوم یا زیردامنهٔ تکراری نسازد.
5. موفقیت و شکست Agent به وضعیت قابل‌فهم سفارش منعکس شود و تمدید همان Site را هدف بگیرد.
6. هیچ API یا رابطی برای خرید VPS مشتری، ثبت SKU هاست‌ایران یا ساخت Site Group Deploy از مسیر این سفارش باقی نماند.
7. آزمون‌ها با Site، Bench، Server، Agent Job و پرداخت mock اجرا شوند و زیرساخت یا پرداخت واقعی نسازند.

## خارج از محدوده

- راه‌اندازی یا خرید VPS اختصاصی برای مشتری.
- ساخت بنچ یا نصب برنامهٔ جدید روی بنچ. برنامه‌های قابل‌انتخاب باید پیشاپیش در Release Group/Bench عمومی Press موجود باشند.
- راه‌اندازی خودکار wildcard DNS/TLS یا provisioning سرور و بنچ عمومی. این‌ها پیش‌نیازهای عملیاتی Press هستند و باید جداگانه در پنل زیرساخت آماده شوند.
- فعال‌کردن پرداخت پولی بدون Merchant ID واقعی، حالت production و تأیید readiness.
