# میزبانی سایت جدید آسومی روی VPS اختصاصی هاست‌ایران

## تصمیم محصول

- ارتقای سایت موجود روی همان زیرساخت و سرور فعلی آن انجام می‌شود؛ برای ارتقا VPS تازه نمی‌خریم.
- هر سایت جدید مشتری روی یک VPS جداگانه از هاست‌ایران میزبانی می‌شود. اطلاعات، بنچ و منابع دو مشتری در یک سرور مشترک قرار نمی‌گیرد.
- سرور توسط آسومی از حساب هاست‌ایران تهیه و از داخل Press مدیریت می‌شود. تا وقتی اتصال خرید رسمی هاست‌ایران و اعتبارنامهٔ API نداریم، خرید سرور دستی است؛ پنل آسومی خرید خودکار یا اتصال تأییدنشده را وانمود نمی‌کند.
- Press پس از آماده‌شدن VPS، آن را به تیم مشتری متصل می‌کند، وضعیت سیستم‌عامل و Agent را تأیید می‌کند، بنچ خصوصی را می‌سازد و سایت و برنامه‌های مجاز را روی همان سرور راه‌اندازی می‌کند.
- زیر‌دامنهٔ `*.asumi.ir` از پراکسی مدیریت‌شدهٔ Press عبور می‌کند. DNS و TLS باید با `Proxy Server Domain` و گواهی‌ای که Press استفاده می‌کند هماهنگ باشد؛ رکورد هر سایت مستقیماً به IP VPS مشتری اشاره نمی‌کند مگر معماری پراکسی عمداً این‌طور تنظیم شود.

## قیمت و سفارش

- Site Planهای «ارتقای سایت موجود» و «ساخت سایت جدید روی VPS اختصاصی» دو محصول جدا می‌مانند.
- قیمت فروش ماهانه از پنل مدیر تنظیم می‌شود. پنل همچنین SKU هاست‌ایران و بهای ماهانهٔ ثبت‌شدهٔ VPS را نگه می‌دارد تا مدیر قیمت فروش را با هزینهٔ زیرساخت مقایسه کند.
- قیمت خرید، تخفیف و تمدید هاست‌ایران ممکن است تغییر کند. مقدار ثبت‌شده در پنل، یادداشت هزینه برای مدیر است و جایگزین قیمت نهایی‌ای که در حساب هاست‌ایران دیده می‌شود نیست.
- سفارش جدید پس از تأیید پرداخت وارد صف «در انتظار تهیهٔ VPS» می‌شود. تا آن زمان هیچ سایت Docker مشترکی ساخته نمی‌شود.
- مدیر شناسهٔ سفارش هاست‌ایران را ثبت می‌کند، VPS آماده‌شده را به‌عنوان `Server` در Press متصل و راه‌اندازی می‌کند، و فقط وقتی سرور فعال و آمادهٔ ساخت سایت باشد تحویل را شروع می‌کند.
- سفارشی که روی VPS اختصاصی می‌رود شامل هزینهٔ VPS و هزینهٔ مدیریت آسومی است؛ پنل قیمت نهایی را مدیر وارد می‌کند. هیچ درصد سود یا قیمت فروش از روی فهرست ارائه‌دهنده حدس زده نمی‌شود.
- پرداخت، پیگیری سفارش و تمدید همچنان از مسیر زرین‌پال و با همان حالت fail-closed اجرا می‌شوند. تا زمان ثبت Merchant ID واقعی و خاموش‌شدن sandbox فروش پولی خاموش می‌ماند.

## گردش تحویل

1. مشتری پلن ساخت سایت را انتخاب می‌کند، زیردامنه و برنامه‌های مجاز را می‌فرستد و پرداخت را انجام می‌دهد.
2. callback زرین‌پال فقط بعد از تأیید واقعی پرداخت، سفارش را `Paid` می‌کند. سفارش برای worker Docker فرستاده نمی‌شود.
3. مدیر VPS را در هاست‌ایران می‌خرد و از مسیر Server استاندارد Press آن را به تیم مشتری وصل می‌کند. فیلدهای HostIran order reference، SKU، IP و Server به سفارش پیوند می‌خورند؛ رمز root یا کلید خصوصی در سفارش ذخیره نمی‌شود.
4. سرویس backend پیش از شروع کار بررسی می‌کند که Server فعال و setup شده باشد، به همان تیم تعلق داشته باشد، برای سایت جدید قابل استفاده باشد، از پراکسی فعال دامنهٔ آسومی عبور کند و برنامه‌های انتخابی از sourceهای نسخهٔ انتخاب‌شده قابل نصب باشند.
5. Press با Site Group Deploy بنچ خصوصی مشتری را روی VPS می‌سازد، برنامه‌های مجاز را نصب می‌کند و سایت را با همان تیم، پلن، نام زیردامنه و سفارش ایجاد می‌کند. Site و deployment فقط به همان سفارش قابل انتساب هستند.
6. سفارش تنها وقتی `Active` می‌شود که Site و Agent موفق باشند و دامنه از پراکسی و TLS مورد انتظار پاسخ دهد. شکست‌ها با شناسهٔ deployment و خطای پاک‌سازی‌شده در پنل مدیر قابل پیگیری و retry هستند.
7. پایان دوره فقط دسترسی همان سایت را طبق چرخهٔ فعلی میزبانی تعلیق می‌کند؛ حذف VPS یا داده به صورت خودکار انجام نمی‌شود. تمدید دستی همان Site و همان سرور را ادامه می‌دهد.

## مرزهای امنیتی و خطا

- هیچ سایت جدیدی روی بنچ مشترک فعلی ساخته یا از آن کپی نمی‌شود.
- فقط مدیر آسومی می‌تواند HostIran order reference، VPS، IP و شروع تحویل را ثبت کند.
- endpoint راه‌اندازی سرور فقط سفارش `Hosting` دارای پرداخت واقعی و تأییدشده، زیردامنهٔ رزروشده و پلن فعال را می‌پذیرد.
- server/plan/team/subdomain/apps دوباره سمت سرور اعتبارسنجی می‌شوند؛ دادهٔ رابط کاربر مرجع قابل اعتماد نیست.
- اسرار SSH، رمز VPS، Merchant ID و اطلاعات محرمانهٔ هاست‌ایران در سفارش، لاگ یا پاسخ API قرار نمی‌گیرند.
- شکست خرید VPS یا راه‌اندازی سایت، سفارش را فعال نشان نمی‌دهد. مدیر می‌تواند سفارش را ادامه دهد یا پس از بازپرداخت واقعی، نتیجه را ثبت کند.
- خرید واقعی VPS، ساخت سرور واقعی و ارسال پرداخت با تست انجام نمی‌شود.

## بیرون از محدودهٔ فاز نخست

- خرید خودکار VPS از هاست‌ایران؛ نیازمند API رسمی و credential حساب کاربر است.
- تمدید خودکار VPS یا پرداخت خودکار هزینهٔ ارائه‌دهنده.
- انتقال خودکار مشتری بین VPSها یا بازیابی disaster به سرور جایگزین.
- اشتراک منابع چند مشتری روی یک VPS برای پایین‌آوردن هزینه.

## معیار پذیرش

1. سفارش ارتقای سایت موجود، سرور آن سایت را عوض نمی‌کند.
2. پرداخت سفارش سایت جدید هیچ‌وقت `create_hosted_site` روی Docker agent را اجرا نمی‌کند.
3. سایت جدید بدون ثبت VPS و server آماده، قابل تحویل یا فعال‌شدن نیست.
4. سرور نامرتبط، آماده‌نشده، غیرفعال، فاقد پراکسی، متعلق به تیم دیگر یا دارای برنامهٔ نامجاز رد می‌شود.
5. سایت ساخته‌شده باید با تیم، پلن، زیردامنه، Server و برنامه‌های همان سفارش تطبیق داشته باشد.
6. تکرار درخواست تحویل، همان deployment را برمی‌گرداند و بنچ یا سایت دومی نمی‌سازد.
7. خطای راه‌اندازی و retry در پنل مدیر قابل مشاهده است؛ مشتری اسرار یا جزئیات داخلی نمی‌بیند.
8. تست‌ها از Server، Site Group Deploy، پرداخت واقعی یا VPS واقعی استفاده نمی‌کنند.
9. آماده‌بودن SMTP، پرداخت تولید، root domain/proxy/TLS و سرور/bench مناسب قبل از فروش یا تحویل بررسی می‌شود.
